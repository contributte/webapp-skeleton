# Webapp Skeleton Design

Webapp Skeleton renders a front cover page, an admin sign-in and a secured admin page, error pages, a PDF example
and an e-mail example. Developers who start from the skeleton see it first; they replace most of it with their own UI.

## Principles

- **Bootstrap 4 from a CDN, plain CSS on top.** Front and admin load Bootstrap from cdnjs and one stylesheet each
  from `www/assets/`; there is no build step to learn before the first change.
- **One layout per module, one shared shell.** `Base/templates/@layout.latte` holds the HTML head; module layouts
  add assets and blocks. A developer can delete a module with its layout and nothing else breaks.
- **Examples stay minimal.** Each screen shows one integration (sign-in, form, PDF, mail) with the least markup that
  works, so it is easy to read and easy to delete.
- **Error pages work without the application.** The 500 pages are static `.phtml` files with inline CSS, so they
  render even when Latte or the container fails.

## Inventory

- HTML shell with title, meta tags and `#main` / `#content` blocks: `app/UI/Modules/Base/templates/@layout.latte`
- Front layout, a Bootstrap cover page with the navigation: `app/UI/Modules/Front/templates/@layout.latte`
- Front home: `app/UI/Modules/Front/Home/templates/default.latte`
- Front 4xx pages: `app/UI/Modules/Front/Error4xx/templates/{403,404,405,410,4xx}.latte`
- 500 page printed by `BaseErrorPresenter`: `app/UI/Modules/Base/templates/500.phtml`
- Tracy production error page: `resources/tracy/500.phtml`, with `500.json` and `500.txt`
- Admin layout: `app/UI/Modules/Admin/templates/@layout.latte`
- Admin sign-in form: `app/UI/Modules/Admin/Sign/templates/in.latte`
- Admin home with the order form: `app/UI/Modules/Admin/Home/templates/default.latte`
- PDF page and layout: `app/UI/Modules/Pdf/Home/templates/default.latte`, `app/UI/Modules/Pdf/templates/@layout.latte`
- PDF document: `resources/pdf/example.latte`
- Mailing page, layout and e-mail body: `app/UI/Modules/Mailing/Home/templates/`
- E-mail layout and an unused sign-in e-mail: `resources/mail/@layout.latte`, `resources/mail/signIn/signIn.latte`
- Scripts: `www/assets/front.js` and `www/assets/admin.js` only log to the console.

## Layout

- Front: a flex cover container, `max-width: 42em`, with header, main and footer; defined in `www/assets/front.css`.
- Admin: the body is a flex box that centers its content vertically; the sign-in form is `max-width: 420px`. Defined
  in `www/assets/admin.css`.
- Spacing uses Bootstrap 4 utilities (`mb-4`, `p-3`, `mt-auto`); there is no custom spacing scale.
- The PDF and mailing pages use their own standalone layouts with inline `<style>` blocks, `max-width` 800 px and 600 px.

## Typography

- Front and admin use the Bootstrap 4 font stack; neither stylesheet sets `font-family`.
- The PDF and mailing pages use Georgia at 18 px from their inline styles. The 500 pages use Verdana or sans-serif.

## Colors and Tokens

- Source of truth: `www/assets/front.css` and `www/assets/admin.css`. There are no CSS variables or tokens.
- Front: dark background `#333`, white text and links, white secondary button.
- Admin: light background `#f5f5f5`, Bootstrap primary for the sign-in button, `btn-danger` for logout.
- The Tracy 500 page defines `--main-color` and `--stroke-color` in `resources/tracy/500.phtml`.

## States

- Empty: no lists exist, so there is no empty state.
- Loading: no AJAX; every action is a full page load.
- Error: sign-in errors render as `alert alert-danger` above the form; 4xx pages pick the template by status code
  and fall back to `4xx.latte`; server errors show the static 500 page.
- Success: flash messages are rendered only by the PDF and mailing layouts. Front and admin layouts don't print
  `$flashes`, so the sign-out and "logged out for inactivity" messages are not visible.

## Accessibility

- The sign-in inputs have real `<label>` elements and `required`; the alert has `role="alert"`.
- Known gaps: `<html>` in the base layout has no `lang`, the sign-in logo has an empty `alt`, and front links use
  white on `#333` with 50 % opacity for inactive navigation items.

## Dark Mode

- No dark mode switch. The front page is dark by design and the admin is light; neither follows
  `prefers-color-scheme`.

## Responsive

- `front.css` has one breakpoint, `min-width: 48em`: the brand floats left and the navigation right. Below it
  both are centered.
- The admin form is fluid up to 420 px. The viewport meta tag is set in the base layout.

## Changing the UI

- `Front/templates/@layout.latte` overrides `#main` and never includes `#content`. Front templates, including the
  home page and the 4xx pages, render their `#content` only after the layout includes it.
- Front loads Bootstrap 4.3.1 and admin loads 4.2.1. Change both together.
- Templates read the signed-in user from `$_user`; `$user` is removed by `App\Model\Latte\TemplateFactory`.
- `CompilerTest` compiles every `*.latte` in `app/`; templates in `resources/` are not compiled by any test.
- Links between modules use absolute names (`:Front:Home:`, `:Admin:Sign:in`); the targets are in `App\Model\App`.
